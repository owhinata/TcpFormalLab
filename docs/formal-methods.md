# 形式手法

Safety は悪い状態に到達しないこと、Liveness は明示された条件下で進行することです。TLA+ ではアプリケーションの操作受付、Task と停止処理の順序を抽象化し、意図的なバグの反例を時間順に追って必要な制御を考えます。TLC の成功は指定した有限モデルと設定の範囲内の結果です。Fairness は選択に関する仮定であり、外部 I/O の完了や通信成功を無条件に保証しません。

Lean では明示した仮定のもとで純粋な関数や数学的性質を証明します。tactic の意味を順に確認します。C# のテストは具体的な実行例を確認します。いずれも .NET 自体や C# 非同期実装全体の証明ではありません。API の契約、アプリケーションが保証する性質、OS・ネットワークの環境仮定を区別し、検査・証明・テスト・未検証を記録します。

現在の Client モデルは入門教材で、safety のみを扱います。線形化点、refinement、I/O と liveness は今後の課題です。
